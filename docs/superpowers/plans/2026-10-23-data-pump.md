# Data Pump (export / import without SSH) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Oracle Data Pump export, import and job monitoring from rsqldev, with dump files moved between the server directory and the laptop over the database connection.

**Architecture:** `core/src/datapump.rs` generates every SQL and PL/SQL text (DBMS_DATAPUMP blocks, job and file queries, upload chunks) and keeps the local file list; it is unit-tested. Downloads stream a `BFILE` through a new `Backend::read_server_file` run by a new worker command; uploads reuse `Cmd::ExecBinds` with a BLOB chunk written by `UTL_FILE.PUT_RAW`. The app adds Export / Import dialogs, a transfer runner on its own session, and a Jobs & Files tab.

**Tech Stack:** Rust, `oracle` 0.6.3 (ODPI-C; `sql_type::Bfile` implements `Read + Seek`), wxDragon, serde/toml.

**Spec:** `docs/superpowers/specs/2026-10-23-data-pump-design.md`

## Global Constraints

- Oracle only, on-premise 12.2+, single instance or RAC, any edition. Autonomous / RDS out of scope.
- No SSH, no OS account, no `expdp` binary: only SQL and PL/SQL over the connection.
- Never hold a whole dump in memory: download in 1 MiB reads, upload 4 MiB per round trip written as 32767-byte `PUT_RAW` calls.
- Jobs start with `DBMS_DATAPUMP.START_JOB(h, cluster_ok => 0)` and end with `DETACH`, so they outlive the app.
- Job names `RSQ_EXP_YYYYMMDD_HH24MISS` / `RSQ_IMP_YYYYMMDD_HH24MISS`; default files `<JOB>.dmp` (`<JOB>_%U.dmp` when parallel > 1 or a file size is set) and `<JOB>.log`.
- Compression other than metadata-only and any encryption are opt-in and labelled "needs Advanced Compression" / "needs Advanced Security".
- The encryption password never appears in a preview, worksheet or autosave: blocks use the `:password` placeholder.
- Parallel > 1 disabled on Standard Edition (banner of `V$VERSION` without "Enterprise").
- Every generated block is shown before it runs, with Run and Copy to Worksheet (table editor pattern).
- Workflow: commit per task; push a few commits at once; CI compiles and runs `cargo test -p rsqldev-core`; no local full builds.

**Amendment to the spec's "How":** progress comes from `V$SESSION_LONGOPS` (`opname = job name`, `sofar / totalwork`) plus the job's log file, not `ATTACH` + `GET_STATUS`: the backend has no OUT-bind path for the `ku$_Status` object, and longops + log give percent and current work without one. `ATTACH` is still used for Stop / Resume / Kill. Database identity for the files list is `SYS_CONTEXT('USERENV','DB_UNIQUE_NAME')` + `SYS_CONTEXT('USERENV','CON_NAME')` (V$DATABASE needs extra privileges).

## Review Focus

1. Directory or file names with quotes, spaces or `..`: everything a user types is validated (`[A-Za-z0-9_.$#%-]+`, no `..`) or passed as a bind, never pasted into SQL raw → Task 1 test `names_are_validated`, Task 3 test `upload_and_file_sql_bind_names`.
2. A download interrupted (cancel, connection drop, disk full): the `.part` file stays and the next Download resumes from its size; the final file appears only when complete → Task 5 test `part_path_and_resume_offset`.
3. Missing privileges or a missing file (`ORA-29283`, `ORA-22285`, `ORA-39002`, `PLS-00201 UTL_FILE`, `ORA-31631`): a one-line hint with the GRANT to ask for, not a raw stack → Task 2 test `hints_name_the_grant`.
4. Downloading a dump while its job still runs (file incomplete): refused with "job is still running" → Task 8 step (state check before Download), Task 2 test `job_running_check_sql`.
5. Parallel dumps (`%U`): all pieces found after the job ends, the list stops at the first missing number → Task 1 test `percent_u_candidates`.
